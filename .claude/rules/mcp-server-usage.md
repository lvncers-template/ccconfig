# MCP (Model Context Protocol) Server Usage

## 基本方針

使えるMCPがあれば必ず使う。
手動実装・推測・一般的な回答より、MCPツールによる実際のデータ取得を優先する。

## 有効化チェック（必須・最優先）

MCPツールを使う前に、必ず有効化されているか確認する。

1. 利用可能なMCPサーバー・ツールが存在するか確認する
2. **無効な場合は作業を中断し、ユーザーに有効化を依頼する**
   - 推測・手動実装・一般的な回答で代用しない
   - 「MCPが無効のため先に有効化してください。有効化後に続行します」と伝えて会話を止める
3. 有効化の確認が取れるまで、MCPが必要なタスクは進めない

## MCPサーバー一覧

| ジャンル           | サーバー         | いつ使う                                          | 主な用途                                                                          |
| ------------------ | ---------------- | ------------------------------------------------- | --------------------------------------------------------------------------------- |
| 開発・デバッグ     | Next.js DevTools | Next.jsプロジェクトのエラー・実装・デバッグ       | エラー検出・原因調査、ページメタデータ・Server Actions確認、ライブ状態のクエリ    |
| 開発・デバッグ     | Chrome DevTools  | フロントエンドの問題調査・パフォーマンス分析      | コンソールログ・ネットワーク、パフォーマンスボトルネック、DOM・ブラウザ固有の問題 |
| デザイン           | Figma            | UIデザインの参照・実装・レビュー                  | デザイン仕様の確認、コンポーネント・スタイルの取得、デザインと実装の突合          |
| コラボレーション   | Notion           | Notion上のドキュメント・タスク・ナレッジ操作      | ページ検索・作成・更新、データベース操作、仕様書・議事録の参照                    |
| コラボレーション   | Slack            | Slack連携・チームコミュニケーション               | チャンネル検索、メッセージ送受信、スレッド・Canvas操作、ユーザー情報取得          |
| インフラ・クラウド | Supabase         | DB操作・認証・ストレージに関する実装・確認すべて  | CRUD、RLSポリシー、型安全なデータベース操作                                       |
| インフラ・クラウド | AWS              | AWSリソースの操作・調査・デプロイ                 | EC2・S3・Lambda等のリソース確認、IAM・リージョン設定、インフラ構成の調査          |
| 調査・ドキュメント | Deepwiki         | ユーザーが外部OSSの調査を明示的に依頼したときのみ | サードパーティライブラリ・フレームワークのドキュメント検索                        |

設定はプロジェクトルートの `.mcp.json` を参照（`.claude/mcp.json` ではない。Claude Code はこのパスを読まない）。プレースホルダ（`<PROJECT_REF>` 等）は各自の環境値に置き換える。
